# F-Guard — Forest Monitoring Mobile App

**UI/UX DESIGN** | **MOBILE APPLICATION** | **FIGMA**

F-Guard is a mobile application concept designed to help forestry officers monitor forest surveillance devices, review potential illegal logging alerts, and access incident location information. The interface focuses on map-based monitoring, alert management, device registration, activity history, and account settings.

## 01. Project Overview

### Project Description

F-Guard is a forest monitoring system concept developed as part of a Smart City project at the Informatics Engineering Study Program, University of Mataram, in 2025.

The proposed system combines solar-powered monitoring devices, sound detection, location tracking, and a mobile application. This portfolio project focuses specifically on the **mobile application's UI/UX design**, rather than hardware engineering or backend implementation.

The application is intended to support forestry and environmental agency officers, conservation patrol teams, and disaster response personnel in monitoring device status and receiving information about potential incidents.

### Problem Statement

Forest monitoring across remote areas can be challenging because of limited field access, the scale of forest coverage, and delays in identifying illegal logging activities.

The proposed F-Guard system addresses these challenges through a monitoring concept that delivers incident information to a mobile application. The interface therefore needs to present alerts, device locations, and historical activity in a way that supports quick information retrieval and response.

### Design Objectives

- Organize forest monitoring information in a clear mobile dashboard.
- Make incident locations easy to identify through map-based visualization.
- Present alert categories, timestamps, and incident details in a structured format.
- Simplify device registration and monitoring.
- Provide accessible navigation to alerts, history, information, and account settings.
- Support operational workflows for forestry officers and related stakeholders.

### Target Users

The application is intended for:

- Government forestry and environmental agency officers.
- Conservation patrol teams and forest rangers.
- Disaster response teams.

### Design Scope

The interface concepts documented in the proposal cover the following screens and user flows:

**1. Login**

A login interface with email, username, and password fields, plus a route to account registration.

**2. Registration**

An account creation flow that collects user information, includes password confirmation, and displays an account creation confirmation screen.

**3. Home Dashboard**

A monitoring dashboard containing a search field, an alert visibility control, a map with location markers, and an overview of alarm events.

**4. Add Device**

A device registration flow that includes a device name, map-based location selection, and verification through a QR code or device serial number.

**5. Alerts and Alert Details**

An alert overview with map markers and incident cards, alongside a detail screen showing location coordinates, alert type, event time, and a navigation action.

**6. History and Activity Log**

A calendar-based interface for reviewing activity by date range, including Today, Last 8 Days, and Last Month, with corresponding device activity records.

**7. Information Center**

A searchable information page containing categories such as FAQs, Device Info, and About Us, together with a detail view for selected topics.

**8. Account and Settings**

Profile viewing and editing, logout, and settings categories for account, notifications, appearance, privacy and security, sound, and language.

### Key Design Considerations

- **Information hierarchy:** Prioritize active alerts and incident details.
- **Map-based monitoring:** Use geographic markers to help users locate reported events.
- **Alert recognition:** Distinguish incident types and statuses using clear visual elements.
- **Efficient navigation:** Provide consistent access to key monitoring sections.
- **Historical traceability:** Organize activity records by date and time.
- **Consistent interface patterns:** Reuse components and layouts across related screens.

### Project Outcome

The proposal documents mobile application mockups covering authentication, monitoring, device registration, alerts, activity history, information, and account management.

These designs illustrate the proposed user experience for a forest monitoring system. They should be presented as interface concepts unless a functioning application and its implementation can be independently demonstrated.

### Design Insights

The interface concepts highlight several design opportunities:

- **Incident visibility:** Combining maps with alert summaries helps users review spatial and event information in one place.
- **Action-oriented details:** Presenting incident coordinates and a location action alongside alert information supports field response workflows.
- **Device management:** A dedicated registration flow separates device setup from routine monitoring.
- **Historical review:** Calendar-based filtering helps organize previously recorded activity.
- **Structured information:** Search and categorized information pages provide an organized way to access application guidance.

These insights describe the design rationale and proposed interface structure, not verified usability outcomes.

### Usefulness

The design provides a proposed mobile interface for consolidating forest monitoring information, reviewing incidents, managing devices, and accessing activity records.

Its structure is intended to help forestry officers move between monitoring, investigation, and device management tasks without navigating unrelated screens.

### Practical Application

The interface concept could serve as a design reference for a forest monitoring application connected to IoT devices and an incident detection system.

Further prototyping, usability testing with forestry officers, and technical integration would be needed to validate the design in real operational conditions.
